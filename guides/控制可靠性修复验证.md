## 修复内容

| 项目 | 实现 | 证据 |
| --- | --- | --- |
| HA 并发指令覆盖 | 每台冰箱独立锁，串行读取、校验、写入和确认，后台轮询也等待当前指令 | 原版并发模拟丢失调温或制冰改动；回归测试保留两项 |
| 缺字段补零 | 关键字段必须存在并合法；未上报的可选隔室、诊断字段不写入 | 空状态、缺字段、非法值均阻止写入；可选字段缺失不补零 |
| 控制范围 | 仅允许三项温度和七项功能写入，校验整数、范围、离线及本体操作状态 | 越界、非整数、只读字段和本体状态守卫测试 |
| Nanoe 与互斥模式 | 使用最新状态及本次目标温度；统一互斥微冻和母乳珍藏 | 缓存过期、组合温度更新、模式互斥测试 |
| 写入确认 | 单次写入，最多三次读取；未确认或认证失败报告错误，绝不自动重发 | 延迟状态、未应用指令、认证错误与锁释放测试 |
| 传输安全 | 固定松下自签名证书 DER SHA-256 指纹；禁止重定向；使用响应上下文管理器 | 指纹参数、证书不匹配、响应释放、HTTP 401/403 分类测试；公开页面指纹连接 HTTP 200 |
| 上游 HA 兼容性 | 先注册账号服务设备，再通过 `via_device_id` 关联家电，保持原 identifier | 账号注册顺序、冰箱 identifier、空调及浴霸实体构造测试 |
| CI | Python 3.14 + HA 2026.10.1 + pytest 9.1.1，执行测试及 compileall | 工作流结构和 JSON 校验通过；尚未在 GitHub 运行 |

## 验证边界

本地修复验证阶段没有重新登录松下账号、发送冰箱控制指令、修改 HA 生产文件、重载或重启。后续部署按用户授权进行；真实设备控制、云端更新延迟、自然运行与物理行为验收仍需单独验证。

HACS 正式发布需对齐 manifest、Git tag 和 GitHub Release。生产升级需备份当前集成并保留回退版本，再按授权部署、检查配置、重启及核对实体与日志。
